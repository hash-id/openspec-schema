# Odoo hints (Odoo 18 and later)

For a repo or change with `__manifest__.py` on Odoo 18.0 or newer. Odoo is a web application and exposes JSON-RPC and XML-RPC, so also read `web-top10-2025.md`, `api-top10-2023.md`, and `cwe-top25-2025.md`. Each hint says where a category usually shows up in Odoo code. The category labels in parentheses are this skill's own mapping; the facts come from the sources below. These hints were not checked against Odoo 17 or earlier.

- Model access (A01, API1, API5, CWE-862) [SEC]: every model needs `ir.model.access` rows. A row with an empty `group_id` is granted to every user, including portal and public users. If no row matches, the user has no access. Rights are additive across a user's groups.
- Record rules (A01, API1, CWE-639) [SEC]: `ir.rule` is default-allow: if access rights grant access and no rule applies, access is granted. Global rules (no groups) intersect, so each one restricts further. Group rules unify, so adding one can expand access up to the global bounds. Several global rules can leave no access at all. Check each `domain_force`. The `perm_*` flags on a rule choose which operations it is checked for.
- Field access (API3, CWE-200) [SEC]: a field's `groups` attribute removes it from views and `fields_get()`, and an explicit read or write raises an access error.
- Public methods (API5, A01) [SEC]: any public method can be called over RPC with chosen arguments. Methods starting with `_` are not callable from an action button or the external API. The record and the arguments cannot be trusted, because ACLs are verified only during CRUD operations. Making a method private is not enough.
- `sudo()` (A01, CWE-863) [SUDO]: superuser mode "does not change the current user, and simply bypasses access rights checks", and the docstring warns it "could cause data access to cross the boundaries of record rules", for example records of different companies. Check that its result is not returned to, or acted on for, a user who could not read it.
- Controllers (A01, A07, CWE-306, CWE-352) [HTTP]: check each `@http.route`'s `auth`. `user` runs with the user's rights. `bearer` authenticates with an API token in the `Authorization` header and otherwise falls back to the session as `user` does. `public` runs as the shared Public user when nobody is logged in. `none` has no access to the current user and is meant for framework and authentication modules. `csrf` is on by default for `http`-type requests and off by default for the JSON request type (named `'json'` in the 18.0 docstring and `'jsonrpc'` in 19.0). Look at any `csrf=False` and at `cors`. 19.0 adds a `captcha` route option.
- Raw SQL (A05, CWE-89) [SEC]: use the ORM when it can do the job. Never build a query by string concatenation or `%` formatting; pass parameters. The 19.0 docs also show the `SQL` wrapper and `env.execute_query`.
- Domain injection (A05, API3) [SEC, 19.0 docs only]: a domain list built from user input can be extended by the user (the docs' example is `['|', ('id', '>', 0)]`). Combine user domains with the security domain through `Domain`, not by list concatenation. The 18.0 docs do not have this section; the risk of concatenating a user-supplied domain is the same there.
- QWeb output (A05, CWE-79) [QWEB, SEC]: `t-raw` never escapes and has been deprecated since Odoo 15; use `t-out` with a `Markup` value. `t-esc` is an alias for `t-out`. The security page calls `t-raw` for rich text "a frequent XSS vector".
- Building HTML in Python (A05, CWE-79) [SEC]: use `Markup` with `%` or `.format`, not f-strings; `escape` joins two `Markup` objects. Escaping is mandatory whenever data is mixed with code. Sanitizing is not a substitute for escaping.
- Evaluation (A05, CWE-94) [SEC]: avoid `eval`. `safe_eval` "must be reserved for trusted privileged users only". For plain data use `ast.literal_eval()` or `json.loads()`.
- Dynamic attributes (CWE-639) [SEC]: `getattr(record, name)` with a user-supplied name can reach private attributes and methods. Use `record[name]` and still validate the record id and the field.

Sources (read from the source repositories on 2026-10-15):
- [SEC] `odoo/documentation`, `content/developer/reference/backend/security.rst`, branches 18.0 and 19.0 (https://www.odoo.com/documentation/18.0/developer/reference/backend/security.html). The 19.0 text adds the `SQL` wrapper, `execute_query`, and the domain-injection section; the other points are the same in both.
- [HTTP] `odoo/odoo`, `odoo/http.py`, the `route()` docstring, branches 18.0 and 19.0. `bearer` appears in both. 19.0 names the JSON request type `'jsonrpc'` and adds the `captcha` and `save_session` parameters.
- [SUDO] `odoo/odoo`, the `sudo()` docstring: `odoo/models.py` on 18.0, `odoo/orm/models.py` on 19.0. The text is the same.
- [QWEB] `odoo/documentation`, `content/developer/reference/frontend/qweb.rst`, "Deprecated output directives", branches 18.0 and 19.0.
