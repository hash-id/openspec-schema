# OWASP API Security Top 10:2023 (HTTP and RPC APIs)

For route handlers, OpenAPI-described services, GraphQL, JSON-RPC and XML-RPC endpoints, and webhooks. Walk each line once.

- API1 Broken Object Level Authorization: can a caller read or change another user's object by changing an ID?
- API2 Broken Authentication: are tokens, keys, login, and credential flows sound, including forgot-password and reset-password flows?
- API3 Broken Object Property Level Authorization: can a caller read or write properties they should not (over-exposed fields, mass assignment)?
- API4 Unrestricted Resource Consumption: are there limits on request size, rate, cost, and paid third-party calls?
- API5 Broken Function Level Authorization: can an ordinary caller reach an admin or privileged function?
- API6 Unrestricted Access to Sensitive Business Flows: can automation abuse a flow (signup, purchase, booking) at scale?
- API7 Server Side Request Forgery: does the server fetch a URL the caller supplies?
- API8 Security Misconfiguration: CORS, headers, verbose errors, default settings?
- API9 Improper Inventory Management: are old versions, debug endpoints, or undocumented endpoints still exposed?
- API10 Unsafe Consumption of APIs: are responses from third-party APIs trusted without validation?
