# OWASP Non-Human Identities (NHI) Top 10 (2025)

For service accounts, API keys, tokens, bots, and other credentials that software uses to act. Walk each line once.

- NHI1 Improper Offboarding: is a machine identity removed when its owner, service, or integration goes away?
- NHI2 Secret Leakage: can its secret end up in code, logs, images, tickets, or chat?
- NHI3 Vulnerable Third-Party NHI: does it grant a third-party tool, IDE extension, or SaaS integration access that the tool could abuse?
- NHI4 Insecure Authentication: does it authenticate with weak, static, or deprecated methods?
- NHI5 Overprivileged NHI: does it hold more permissions than its job needs?
- NHI6 Insecure Cloud Deployment Configurations: do CI/CD pipelines authenticate to the cloud with static credentials, or with an over-broad OpenID Connect trust?
- NHI7 Long-Lived Secrets: does the secret lack expiry or rotation?
- NHI8 Environment Isolation: are dev, test, and production identities kept apart?
- NHI9 NHI Reuse: is one identity shared across services or environments?
- NHI10 Human Use of NHI: can a person use the machine identity directly, hiding who acted?
